# claude-yemot-hooks

חיבור בין [ימות המשיח](https://www.call2all.co.il) ל‑Claude Code דרך hooks.

* **צינתוק (התראה)** — Claude שולח צינתוק לנייד כשהוא צריך אותך (RunTzintuk). ללא Python: ה‑hook רץ עם PowerShell מובנה.
* **מענה טלפוני** — Claude מביא אותך לשלוחת `api` בימות, מקריא שאלה, ואתה עונה בהקשה (DTMF). התשובה חוזרת ל‑Claude כתגובת ה‑hook. שתי דרכי חיוג:
  * **שיחת גישור** (CallExtensionBridging) — חיבור מיידי אוטומטי לשלוחה.
  * **צינתוק + מענה** (RunTzintuk) — נשלח צינתוק, ואתה חוזר למספר (מזהה מתקשר שמפנה לשלוחה) ונכנס אליה לענות.

מצב המענה דורש שרת רץ ([main.py](main.py)). ההגדרה נעשית דרך ממשק HTML עצמאי — בלי backend, בלי Python בצד הלקוח.

## אירועים נתמכים

**PreToolUse** (שאלת AskUserQuestion) ו‑**PermissionRequest** — תומכים גם במענה טלפוני (קלט שחוזר לקלוד). **Stop**, **SubagentStop**, **UserPromptSubmit** — צינתוק (התראה) בלבד.

## ממשק ההגדרה

הממשק הוא דף סטטי בצד לקוח. אפשר לפתוח מקומית את [yemot_hooks_config.html](yemot_hooks_config.html) ב‑Chrome/Edge, או לארח אותו ב‑**GitHub Pages** (ראה למטה). הדף פונה ישירות ל‑API של ימות מהדפדפן; hooks של מענה דורשים בנוסף שרת גשר רץ בכתובת ציבורית.

1. **חיבור** — טוקן + כתובת שרת. סמן "קרא טוקן מ‑`$env:YEMOT_TOKEN`" (מומלץ — לא נשמר טוקן גלוי) או הזן ידנית. לחיצה אחת על **"התחבר וטען הכל"** בודקת חיבור וטוענת תבניות/רשימות/מזהי מתקשר.
2. **נתוני החשבון** — רשימות צינתוק, תבניות ומזהי מתקשר מאושרים.
3. **יצירת שלוחה** — נווט בעץ (כותרות השלוחות מוצגות); שלוחות `api` שאתה עובר עליהן נאספות אוטומטית לבורר ה‑ivr_path. בחר סוג `tzintuk` (הרשמה) או `api` (webhook לשרת).
4. **Hooks** — הוסף כמה hooks שתרצה, **כל אחד בנפרד**. לכל hook פעולה:
   - **צינתוק — התראה בלבד** (RunTzintuk, אפשר async).
   - **שיחת גישור + מענה** / **צינתוק + מענה בשלוחה** — איסוף תשובה שחוזרת ל‑Claude.
5. **שמירה** — גלובלי או פרויקט. "פתח, מזג ושמור" מוסיף רק את ה‑hooks של הכלי ומשאיר כל השאר. הפעל מחדש את הסשן.

> **רשימות צינתוק:** שם רשימה מופיע ב‑`getlists` (ובבורר) רק *אחרי* שמתקשר חייג לשלוחת ההרשמה ונרשם.

### אירוח ב‑GitHub Pages

ה‑workflow ב‑[.github/workflows/pages.yml](.github/workflows/pages.yml) מפרסם את דף ההגדרה אוטומטית: כל push ל‑`main`/`master` מעתיק את `yemot_hooks_config.html` ל‑`index.html` ומעלה ל‑Pages. הפעלה חד‑פעמית: **Settings → Pages → Source: GitHub Actions**. הכתובת: `https://<user>.github.io/<repo>/`.

> הדף פונה ישירות ל‑`call2all.co.il` מהדפדפן. אם הדפדפן חוסם CORS מכתובת ה‑Pages — הרץ את הדף מקומית.

## מענה טלפוני

### מקור האפשרויות

האפשרויות תמיד נבנות מהשאלה של קלוד (לא ידני):

| מצב | מתי | מה קורה |
|-----|-----|---------|
| **מהשאלה של קלוד** (askuser) | PreToolUse על `AskUserQuestion` | התפריט נבנה בזמן ריצה מ‑`tool_input.questions[].options[]`. מתווספת "אחר" לטקסט חופשי. הבחירה חוזרת כ‑deny+reason. |
| **מהבקשה של קלוד** (permission) | PermissionRequest | השאלה = הבקשה + "לאישור הקש 1, לביטול הקש 2". חוזר כ‑`decision.behavior` allow/deny. |

> **Stop, SubagentStop, UserPromptSubmit** — בממשק הם צינתוק (התראה) בלבד. השרת עדיין מכיר מצב "טקסט חופשי" (open) למי שירחיב אותם ידנית.

לכל hook בוחרים: **התראה** (צינתוק בלבד) או **המתנה לקלט** (מענה דרך שלוחת API). כתובת אחת לשרת (ציבורית — נגישה מהאינטרנט) משמשת גם את ה‑hook (`/ask-hook`) וגם את ימות (`/respond`).

שלוש דרכי חיוג למצב מענה:
- **אני מתקשר בעצמי** (none) — אין חיוג יוצא; אתה מחייג לקו ומנווט לשלוחה. הכי פשוט, לא דורש טוקן/DID.
- **שיחת גישור** — השרת מחייג אליך ומחבר מיידית לשלוחה.
- **צינתוק + חזרה** — נשלח צינתוק ואתה חוזר למספר/נכנס לשלוחה.

**יעד החיוג:** מספרים ישירים (OTHER), תבנית/רשימת תפוצה (TPL), או רשימת צינתוק (TZL) — בדיוק כמו בצינתוק. עם tpl/tzl, המענה הראשון שמגיע לשלוחה קובע.

**"אחר" (טקסט חופשי):** מפעיל `read` נוסף שקולט טקסט חופשי דרך מקלדת (עברית/אנגלית/מספר) — לא ספרות. הטקסט מוזרק ל‑emit במקום ה‑placeholder `__OPEN_TEXT__`.

**פורמט מספרים:** כל מספר נשלח לימות ב‑10 ספרות עם אפס בהתחלה (`+972`/`972` מומר אוטומטית ל‑`0`).

### הרצת השרת

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000
# חשוף את הפורט בכתובת ציבורית (מנהרה / reverse-proxy כלשהם) כדי שימות תגיע ל-/respond
```

הזן את הכתובת הציבורית בממשק ("כתובת השרת") — היא משמשת גם את ה‑hook (`/ask-hook`) וגם את `api_link` של שלוחת ה‑API (`/respond`).

### הזרימה

```
Claude hook  --stdin+config → POST /ask-hook-->  main.py
   שיחת גישור →  CallExtensionBridging  →  ימות מחייג ומחבר לשלוחה מיידית
   צינתוק+מענה →  RunTzintuk             →  ימות מצנתק; אתה חוזר למספר ונכנס לשלוחה
                                          |
שלוחת api  --GET /respond-->  main.py  (תפריט DTMF; ל"אחר" read טקסט נוסף)
                                          |
בחירה  ------------------->  main.py ממפה ל-emit (מזריק טקסט חופשי אם צריך) ומחזיר
                                          |
ה-hook מדפיס emit ל-stdout  ------------>  Claude ממשיך עם הקלט
```

**כמה שאלות במקביל:** השרת מזהה כל שאלה לפי השלוחה (`ApiExtension`), לכן הקצה לכל hook שלוחת `api` נפרדת (ivr_path ייחודי). ה‑hook **חוסם** עד מענה או תום `wait_timeout` (ברירת מחדל 90 שנ'); ללא מענה — לא מודפס כלום ו‑Claude ממשיך.

## אבטחה

- הטוקן = גישה מלאה לחשבון ימות. אל תכניס ל‑git. עדיף `.claude/settings.local.json` (מגונב ב‑`.gitignore`) או משתני סביבה.
- hooks של **צינתוק** מכילים את הטוקן כטקסט גלוי בפקודה.
- hooks של **מענה** אינם מכילים טוקן — הם פונים לשרת המקומי; הטוקן חי רק ב‑`YEMOT_TOKEN` של השרת.
- אם טוקן הודלף — סובב/החלף סיסמה בימות.
